# p4pa-pu-fe

This application is the web frontend of the **Piattaforma Unitaria** product.

See [p4pa-doc](https://github.com/pagopa/p4pa-doc) for further documentation.

## 🧱 Role

- Back-office web application for public administrations and their intermediaries:
  - It allows management of debt positions, debt types, taxonomy, telematic receipts, treasury data, classifications and reconciliations, organizations, operators and clients SIL;
  - It delegates authentication to Selfcare, exchanging the returned id token for an access token through the BFF;
  - It consumes domain APIs exclusively through [p4pa-pu-bff](https://github.com/pagopa/p4pa-pu-bff), and file upload/download through [p4pa-fileshare](https://github.com/pagopa/p4pa-fileshare).

## 🌐 APIs

The application does not expose APIs. HTTP clients, contracts and zod schemas are generated from the OpenAPI specs of the consumed microservices into the git-ignored `generated/` directory.

### 📌 Common HTTP status handled

- `200`: Successful operation;
- `401`: Invalid access token, the user is redirected to the login;
- `403`: Trying to access a not authorized resource.

## 🔗 Dependencies

### 🧩 Microservices

- [p4pa-pu-bff](https://github.com/pagopa/p4pa-pu-bff):
  - To authenticate the user and to access to all domain data and operations;
- [p4pa-fileshare](https://github.com/pagopa/p4pa-fileshare):
  - To upload and download the files of the import/export flows;

### 🔐 External

- [Selfcare](https://selfcare.pagopa.it):
  - To perform the login and obtain the id token exchanged with the BFF.

## 🔧 Configuration

Environment variables live in `.env` (dev/build) and `.env.test` (tests). Only variables prefixed with `VITE_` are exposed to the client bundle: they are read and validated at startup in [`src/utils/config.ts`](src/utils/config.ts), where a validation failure is logged to the console and the default value is used.

On the pipelines the `.env` file is generated by [`env.sh`](env.sh), which converts every `PU_`-prefixed environment variable into an entry of `.env` (see [`.devops/local-templates/setup-env.yaml`](.devops/local-templates/setup-env.yaml)).

### 📌 Relevant configurations

#### 🖥️ Application

| ENV                | DESCRIPTION                                                                                                                          | DEFAULT                                                                                               |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------- |
| ENV                | Env target, used in conditional evaluations and to disable sourcemaps on `PROD`                                                      |                                                                                                       |
| VITE_DEPLOY_PATH   | Deploy subpath, also used as Vite `base`                                                                                             | /piattaformaunitaria                                                                                  |
| VITE_LOGIN_URL     | Selfcare login URL                                                                                                                   | /login                                                                                                |
| VITE_RESOURCES_URL | Template URL/path of the legal resources, supporting the `{BROKER_EXTERNAL_ID}`, `{DOCUMENT_TYPE}` and `{DOC_LANGUAGE}` placeholders | /piattaformaunitaria-legaldocs/{BROKER*EXTERNAL_ID}/{DOCUMENT_TYPE}/{DOC_LANGUAGE}*{DOCUMENT_TYPE}.md |

#### 🔁 Integrations

##### 🧩 Microservices

| ENV                    | DESCRIPTION                                                      | DEFAULT          |
| ---------------------- | ---------------------------------------------------------------- | ---------------- |
| VITE_APIHOST           | Bff microservice URL                                             | http://localhost |
| VITE_FILESHARE_APIHOST | Fileshare microservice URL                                       | http://localhost |
| VITE_API_TIMEOUT       | After this time API requests are aborted, `0` waits indefinitely | 10000            |

##### ⚙️ Code generation

| ENV                  | DESCRIPTION                                        | DEFAULT                  |
| -------------------- | -------------------------------------------------- | ------------------------ |
| OPENAPI_URL          | OpenAPI spec used to generate the Bff client       | `develop` spec on GitHub |
| OPENAPIFILESHARE_URL | OpenAPI spec used to generate the Fileshare client | `develop` spec on GitHub |

#### 🧪 Test

| ENV | DESCRIPTION                                         | DEFAULT |
| --- | --------------------------------------------------- | ------- |
| TZ  | Forces the timezone, to keep date assertions stable | utc     |

## 🛠️ Getting Started

### 📝 Prerequisites

Ensure the following tools are installed on your machine:

1. **Node 20.18.0** (see [.node-version](.node-version))
2. **Yarn 4.9.2** (`corepack enable`)

### 📦 Install

```sh
yarn install
```

### ⚙️ Generate API clients

```sh
yarn generate
```

It regenerates HTTP clients, contracts and zod schemas from the OpenAPI specs. It is run automatically by `yarn dev` and `yarn build`.

### 🏗️ Build

```sh
yarn build
```

### 🧪 Test

#### 📌 Vitest

```sh
yarn test
```

With coverage report:

```sh
yarn coverage
```

### 🚀 Run local

```sh
yarn dev
```

The application is available at http://localhost:1234.

To serve the production build instead:

```sh
yarn preview
```

### 🧹 Lint & format

```sh
yarn lint
yarn lint:fix
yarn prettify
```

### ⚖️ Generate dependencies licenses

```sh
yarn dependency-licenses
```

The report is written to `dependency-licenses/licenses.csv`.

## 🧩 Adding a module to the project

Extra modules live in `src/extra`, one directory per module. [`src/extra/index.ts`](src/extra/index.ts) auto-discovers them at compile time through Vite glob imports, so no registration is needed: it is enough to add the files matching the expected patterns.

```
src/extra/[moduleName]/routes.tsx   // default export: Array<RouteObject>
src/extra/[moduleName]/sidebar.ts   // default export: Array<ISidebarMenuItem>
```
